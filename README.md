# Undertow

Музыкальный клиент для Windows, который я собрал для себя. Хотелось одно окно,
где можно слушать всё: свои лайки, чужие альбомы, новинки любимых артистов и
радио, которое не кончается через двадцать треков. Заодно без рекламы, без
«рекомендаций» из ниоткуда и без подписки, которая решает, что мне доступно.

Внутри Electron и React, звук тянется через `yt-dlp`, метаданные — из YouTube
Music. Яндекс.Музыка подключается, если есть токен и активный Плюс; без Плюса
она просто выключается целиком, потому что 30-секундные превью — это не музыка.

## Что умеет

- **Главная** собирается из того, что я реально слушаю: продолжить, давно не
  слушал, любимые альбомы, новые релизы любимых артистов и «ещё от…». Лишние
  подборки можно скрыть, они запоминаются и возвращаются кнопкой.
- **Поиск** ищет сразу в трёх разрезах: исполнители, альбомы и треки. Альбомы
  и артисты приходят из YouTube Music, треки — из Яндекса первыми, если он
  подключён.
- **Страницы артиста и альбома** открываются откуда угодно: из строки трека, из
  карточки, из плеера. На странице артиста есть «Слушать всё», его альбомы и
  похожие исполнители. Пластинка в строке трека ведёт к альбому, а если альбома
  нет — показывает версии именно этого трека.
- **Новинки** — отдельная вкладка с последними релизами артистов из библиотеки.
  Дата, тип, обложка и число прослушиваний; сгруппировано по годам, свежее
  помечено `new`.
- **Течение** — бесконечный поток по вайбу библиотеки. Собирается из артистов,
  которых я слушаю, и их соседей по графу похожести, подмешивает редкий трек из
  библиотеки и дозаправляется сам. Можно выбрать жанр — чипы строятся по тому,
  что действительно есть в библиотеке. Когда музыка играет, визуализация дышит
  вместе с ней.
- **Радио артиста и «похожее» на трек** — очередь на 60–90 треков, которая не
  повторяется. У артиста она дозаправляется по мере проигрывания; у трека —
  Яндекс отдаёт похожие, YouTube Music — свою очередь, а если этого мало,
  добиваем радио артиста.
- **Очередь** — панель в плеере: перетаскивание, удаление, «в очередь» из любого
  списка и перемешивание (тасуется только то, что впереди). Очередь переживает
  перезапуск и открывается на паузе.
- **Библиотека** — лайки и история. Лайки из Яндекса можно импортировать, при
  активном аккаунте они уходят и обратно на сервер. Старые записи постепенно
  дозаполняются исполнителями, альбомами и длительностями.
- **Плейлисты** — свои списки: создание, добавление из любого списка,
  перетаскивание строк, удаление, экспорт в JSON и импорт своих плейлистов из
  Яндекса (нужен Плюс). Хранятся локально, без Плюса работают как обычные
  ручные списки.
- **Тексты песен** — тянются из LRCLIB. Если для трека есть синхронный LRC,
  строки подсвечиваются по ходу песни, клик по строке перематывает. Если текста
  нет, кнопка просто не появляется.
- **Плеер** — стык треков без паузы или кроссфейд 3/6/12 секунд, выравнивание
  громкости до −18 dBFS RMS (кнопка **HQ**), прогрев следующего трека, кэш
  ссылок и автоповтор, если ссылка на источник протухла.
- **Без Плюса** работают почти все страницы и подборки: артисты, альбомы,
  похожие, радио и поток берутся из YouTube Music. Подписка нужна только для
  самого Яндекса и импорта его плейлистов.

## Какие источники используются

| Что есть у меня | Что играет |
|---|---|
| только YouTube | YouTube |
| токен Яндекса, Плюса нет | YouTube (превью Яндекса не включаются) |
| токен и Плюс активны | Яндекс основной, YouTube добирает |

Токен хранится зашифрованным через `safeStorage` (на Windows — DPAPI) в
`%APPDATA%/Undertow/secrets.json` и в git не попадает. Вставляется один раз в
настройках.

## Как запустить

Для звука нужен `yt-dlp` и Python:

```bash
python -m pip install -U yt-dlp
```

Дальше как обычно:

```bash
npm install
npm run dev
```

`npm run dev` открывает окно с горячей перезагрузкой. Если запускаю на машине с
двумя мониторами, окно в dev само встаёт на второй, чтобы не мешать работе.

Сборка и установщик:

```bash
npm run build      # только out/
npm run dist       # установщик в release/Undertow-Setup-<версия>.exe
npm run dist:dir   # распакованная сборка, без инсталлятора
```

Первый `dist` долго скачивает Electron и NSIS в кэш. Версия берётся из
`package.json` и подставляется в шапку и настройки.

Установщик не подписан, поэтому SmartScreen один раз спросит «Windows защитила
ваш компьютер» — «Подробнее» → «Выполнить в любом случае». Для личной сборки это
нормально.

## Что не сделано и где можно споткнуться

- Офлайн-кэша скачанных треков нет. Лайки, история и страницы артистов работают
  и без сети, но сам звук — только онлайн.
- Без Плюса у части треков из топа артиста не известен альбом: YouTube Music не
  отдаёт его в этих строках. Альбом по такому треку ищется по «артист +
  название».
- FLAC из Яндекса этому аккаунту не отдаётся — сервер понижает качество до MP3
  320. Если тариф начнёт отдавать lossless, автопроба включит его сама.
- Подмена трека на YouTube — поиск по названию, исполнителю и длительности.
  На редких записях и живых версиях может промахнуться.
- Нормализация — это автоуровень по RMS, а не ReplayGain по паспорту трека.
  Треки между собой выравниваются, «эталонная» громкость альбома не гарантируется.
- `yt-dlp` и Python в установщик не входят: на машине они должны быть
  установлены отдельно, иначе в статусе будет «yt-dlp не найден».
- `ffmpeg` не обязателен: Chromium сам декодирует Opus/WebM из `googlevideo.com`.

## Как это устроено

```
src/main/index.ts          окно, dev-режим, запуск
src/main/ipc.ts            каналы между окном и главным процессом
src/main/providers/        YouTube, Яндекс, оркестратор и правила выбора
src/main/{flow,radio,releases,genres}.ts   поток, радио, новинки, жанры
src/main/{library,playlists,lyrics}.ts     библиотека, плейлисты, тексты
src/renderer/src/          интерфейс на React
docs/architecture.md       подробности решений, замеры и грабли
spikes/                    небольшие проверки гипотез
```

В dev-режиме открыт CDP на `127.0.0.1:9222`, поэтому состояние плеера можно
смотреть из консоли:

```bash
node spikes/player-state.mjs
node spikes/cdp.mjs "await window.undertow.state()"
```

Собрать установщик по тегу и приложить его к GitHub Release можно через
workflow в `.github/workflows/release.yml`.
