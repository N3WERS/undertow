# Undertow

**by N3WERS** · v0.1.0

Личный клиент для прослушивания музыки: Electron 45 + React 19 + TypeScript.
Основной источник — YouTube (поиск + поток через `yt-dlp`), Яндекс.Музыка — следующий шаг.

## Что уже работает

- **Главная**: лента YouTube Music — «Новые альбомы и синглы», «В тренде», «Новые клипы»;
  при активном Яндексе его лента идёт первой, YouTube добавляет две секции.
- **Поиск**: Яндекс + YouTube (Яндекс первым, если подключён); бейджи `Я`/`YT` в смешанной выдаче.
- **Подборка подстраивается** — лишнюю секцию можно скрыть крестиком
  (запоминается, возвращается кнопкой в шапке), а имя исполнителя в любой строке
  открывает его страницу. Если исполнителей несколько, каждый — отдельная
  ссылка: и в списках, и в плеере.
- **Старая библиотека дозаполняется** — исполнители, альбомы и обложки
  подтягиваются для уже сохранённых лайков и истории при запуске.
- **Новинки** — отдельная вкладка: последние релизы артистов из вашей
  библиотеки. Каждый релиз — обложка, тип (сингл/EP/альбом), точная дата
  выпуска (из Apple Music; если её нет — год из YouTube Music) и число
  прослушиваний с подписью площадки, откуда оно взято (YouTube). Релизы
  сгруппированы по годам, свежие помечены `new`, клик открывает альбом,
  кнопка на обложке сразу играет его, а имя артиста ведёт на его страницу.
- **Радио артиста** — кнопка на странице исполнителя собирает очередь из его
  треков и похожих артистов, а по мере проигрывания очередь подмешивается сама;
  пластинка в строке открывает альбом трека — настоящий альбом YouTube Music,
  а если его там нет, компактный список версий именно этого трека, а не солянку
  из поиска.
- **Страницы артиста и альбома** — открываются из подборок и карточек:
  обложка, «Слушать всё», альбомы артиста и список треков.
- **Главная от библиотеки** — до шести «Ещё от любимых артистов» с аватарами
  и подписями, «Продолжить слушать»,
  «Любимые альбомы», «Новое от артистов» и «Давно не слушали»; липкая полоса
  чипов для быстрого перехода (липнет к верху и листается стрелками, если не
  влезает), полоска альбомов в секции артиста и кнопка «показать все» у каждой
  подборки.
- **Очередь** — панель в плеере: перетаскивание треков, удаление, «+ в очередь»
  из любого списка и перемешивание (тасует только то, что впереди).
- **Библиотека**: «Мне нравится» и история прослушивания; лайки из Яндекса
  подтягиваются импортом (и уходят обратно на сервер при активном аккаунте).
- **Библиотека без Яндекса**: если токен убран или Плюс кончился, треки Яндекса
  играют найденными копиями с YouTube (пара запоминается, в плеере виден суффикс `· YT`).
- **Всё работает без Плюса**: страницы артиста (топ-треки, альбомы, «Похожие
  исполнители») и альбома, радио с дозаправкой — всё из YouTube Music, как если
  бы это был Яндекс. Подписка не нужна, звук всё так же берётся через yt-dlp.
- **Настройки**: вставка токена Яндекса, проверка Плюса, отключение, перепроверка.
- **Плеер**: play/pause, next/prev, перемотка, громкость, автопереход,
  прогрев следующего трека, кэш ссылок, автоповтор при протухшей ссылке Яндекса.
- **Звук**: стык треков без паузы (или кроссфейд 3/6/12 с) и выравнивание громкости
  до −18 dBFS RMS — через Web Audio и локальный прокси с CORS. Включается галочкой
  в настройках или кнопкой **HQ** в плеере (загорается бирюзовым, когда включена).
- **Горячие клавиши**: `Space` — пауза, `Alt+←/→` — переключение треков.

### Правило выбора провайдера

| Что есть | Что играет |
|---|---|
| нет токена Яндекса | только YouTube |
| токен есть, Плюса нет | только YouTube (30-секундные превью не используется) |
| токен есть, Плюс активен | Яндекс основной, YouTube дополняет |

Токен хранится зашифрованным (`safeStorage`, на Windows — DPAPI) в
`%APPDATA%/Undertow/secrets.json`, в git не попадает.

## Запуск

```bash
npm install
npm run dev        # окно приложения с горячей перезагрузкой
npm run build      # сборка в out/
npm run dist       # установщик Windows в release/Undertow-Setup-<версия>.exe
npm run dist:dir   # только распакованная сборка (release/win-unpacked)
```

Первый запуск `dist` дольше обычного: electron-builder скачивает Electron и NSIS
в кэш. Версия берётся из `package.json` и подставляется в шапку и настройки
(`__APP_VERSION__`), иконка — `build/icon.ico` (из `build/icon.png`, углы
прозрачные: белый фон исходной картинки вырезан маской).

Нужен установленный `yt-dlp`:

```bash
python -m pip install -U yt-dlp
```

Без него приложение запустится, но в статус-баре будет «yt-dlp не найден».
`ffmpeg` пока не обязателен: Chromium сам декодирует Opus/WebM, поэтому
поток идёт напрямую из `googlevideo.com`.

## Структура

```
src/main/index.ts          окно, dev-флаги, форвардинг консоли рендерера
src/main/ipc.ts            типизированные каналы IPC
src/main/ytdlp.ts          поиск (--flat-playlist) и resolve (-g) через yt-dlp
src/main/providers/        интерфейс провайдера, YouTube, Яндекс, оркестратор с правилами
src/main/store.ts          секреты (токен, шифрование через safeStorage)
src/preload/index.ts       contextBridge → window.undertow
src/renderer/src/          React UI (главная, поиск, плеер)
spikes/                    одноразовые проверки гипотез
docs/architecture.md       решения, риски, порядок работ
```

## Проверка плеера без глаз

В dev-режиме открыт CDP на `127.0.0.1:9222`:

```bash
node spikes/player-state.mjs              # состояние <audio>
node spikes/cdp.mjs "await window.undertow.state()"
```

## Известные ограничения

- Офлайн-кэш скачанных треков — не сделан (лайки, история и страницы артистов есть).
- Без Плюса у трека из топа артиста не всегда известен альбом (YouTube Music
  не отдаёт его в этих строках), поэтому «пластинка» есть в основном у треков
  из библиотеки и на странице альбома; альбом по такому треку находится
  поиском по «артист + название».
- FLAC из Яндекса не отдаётся: сервер понижает `quality=lossless` до MP3 320 для этого
  аккаунта. Автопроба включит FLAC сама, если тариф его даст (см. `docs/architecture.md` §4a).
- Подмена на YouTube ищет по названию/исполнителю/длительности и может промахнуться
  на редких треках и живых записях — тогда лучше переключить, чем ждать чуда.
- Нормализация — это автоуровень по RMS, а не ReplayGain по паспорту трека:
  выравнивает треки между собой, но не гарантирует «эталонную» громкость альбома.
- При медленной сети Chromium иногда буферизует (`waiting`), звук на пару секунд замирает.
- Установщик не подписан: Windows SmartScreen покажет «Windows защитила ваш
  компьютер» — «Подробнее» → «Выполнить в любом случае». Это ожидаемо для
  личной сборки.
- В установщик не входит `yt-dlp`/`python`: на машине должен быть установлен
  `python -m pip install -U yt-dlp`, иначе в статусе будет «yt-dlp не найден».
